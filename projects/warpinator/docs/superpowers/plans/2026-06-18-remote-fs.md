# Remote Filesystem (Wave-style) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Enable Warpinator's Project Explorer, file tree, and editor to work on remote filesystems when SSHed into a remote host — identical to Wave Terminal's experience — with no Warp account required.

**Architecture:** Two phases. Phase 1 is a shell script that packages `warp-oss` as `oz.tar.gz` at the SCP-fallback cache path; Warpinator's existing SCP-fallback mechanism auto-uploads it on the next SSH connect, no code changes needed. Phase 2 overrides `download_tarball_url()` for the OSS channel so fresh installs download from GitHub Releases instead of failing silently, backed by a new GHA workflow that builds and publishes the tarball on tag push.

**Tech Stack:** Bash (staging script), Rust (`crates/remote_server/src/setup.rs` — one function), GitHub Actions YAML (release workflow)

## Global Constraints

- Remote: Linux x86_64, Ubuntu 24.04, glibc 2.39 — confirmed via `apps@client-apps`
- Binary naming: tarball must contain a file named `oz`; install script (`install_remote_server.sh`) renames it to `warp-oss` at install time
- Remote install path: `~/.warp-dev/remote-server/warp-oss` (OSS channel rides `dev` arm in `remote_server_dir()` at `setup.rs:349`)
- Local SCP-fallback cache path: `~/.cache/Warp-Oss/remote-server/tarballs/unversioned/linux-x86_64/oz.tar.gz`
- GHA runner: `ubuntu-24.04` (pinned — NOT `ubuntu-latest`; glibc skew causes `--version` failure on remote)
- Tag convention for releases: `v0.YYYY.MM.DD-warpinator`
- Release asset name: `oz-linux-x86_64.tar.gz`
- GitHub Releases URL pattern: `https://github.com/TheophilusChinomona/warpinator/releases/latest/download/oz-{os}-{arch}.tar.gz`
- Never commit to `developer` directly — work on `feature/remote-fs`
- Pre-existing uncommitted bridge changes (`projects/warpinator/bridge/*.js`) are unrelated — do not stage or commit them in this branch

Create `script/stage-remote-server.sh` with this exact content:

```bash
#!/usr/bin/env bash
# Packages warp-oss as the remote-server daemon tarball and stages it at the
# local SCP-fallback cache path so Warpinator can upload it when SSHing into
# a remote host without a Warp account or CDN access.
#
# OSS channel only — targets linux-x86_64 (the channel's binary_name is
# "warp-oss" and remote_server_dir() returns ".warp-dev"; see setup.rs:349).
set -euo pipefail

REPO_ROOT="$(cd "$(dirname "${BASH_SOURCE[0]}")/.." && pwd)"
BINARY="$REPO_ROOT/target/release/warp-oss"
CACHE_DIR="$HOME/.cache/Warp-Oss/remote-server/tarballs/unversioned/linux-x86_64"
CACHE_PATH="$CACHE_DIR/oz.tar.gz"

if [ ! -f "$BINARY" ]; then
  echo "error: $BINARY not found — run 'cargo build --release --bin warp-oss --features gui' first" >&2
  exit 1
fi

TMPDIR="$(mktemp -d)"
trap 'rm -rf "$TMPDIR"' EXIT

cp "$BINARY" "$TMPDIR/oz"
# strip is a size optimization (~950MB debug → ~50MB release+stripped).
# It is safe on a dynamically-linked Rust binary and does not affect --version.
# Guard: if strip is not installed, proceed without it (binary is larger but functional).
if command -v strip >/dev/null 2>&1; then
  strip "$TMPDIR/oz"
else
  echo "warning: strip not found — binary will be larger" >&2
fi
tar czf "$TMPDIR/oz.tar.gz" -C "$TMPDIR" oz

mkdir -p "$CACHE_DIR"
mv "$TMPDIR/oz.tar.gz" "$CACHE_PATH"

SIZE="$(du -sh "$CACHE_PATH" 2>/dev/null | cut -f1 || stat -c%s "$CACHE_PATH")"
echo "Staged remote-server tarball at $CACHE_PATH ($SIZE)"
echo "NOTE: if a daemon is already running on a remote, kill it first (pkill warp-oss) so Warpinator picks up the new binary on reconnect."
```

```rust
pub fn download_tarball_url(platform: &RemotePlatform) -> String {
    // warpinator: for OSS builds, serve tarballs from GitHub Releases instead
    // of the Warp CDN (which requires an account and uses query-string routing
    // that GitHub's asset URLs don't support).
    if matches!(ChannelState::channel(), Channel::Oss) {
        return format!(
            "https://github.com/TheophilusChinomona/warpinator/releases/latest/download/oz-{}-{}.tar.gz",
            platform.os.as_str(),
            platform.arch.as_str()
        );
    }
    format!(
        "{}?package=tar&os={}&arch={}&channel={}{}",
        download_url(),
        platform.os.as_str(),
        platform.arch.as_str(),
        download_channel(),
        version_query(),
    )
}
```

### Task 3: Phase 2b — GitHub Actions release workflow

**Files:**
- Create: `.github/workflows/warpinator-release.yml`

**Interfaces:**
- Trigger: `push: tags: ['v*-warpinator']`
- Produces: GitHub Release with asset `oz-linux-x86_64.tar.gz` at `releases/latest/download/oz-linux-x86_64.tar.gz` — matches the URL pattern in Task 2

- [ ] **Step 1: Create the release workflow**

Create `.github/workflows/warpinator-release.yml`:

```yaml
name: warpinator Release

on:
  push:
    tags:
      - 'v*-warpinator'

env:
  CARGO_TERM_COLOR: always
  RUSTFLAGS: -C debuginfo=line-tables-only --cfg=web_sys_unstable_apis

jobs:
  release:
    name: Build & Publish warpinator remote-server
    # ubuntu-24.04 is pinned — NOT ubuntu-latest. The remote target (Ubuntu 24.04,
    # glibc 2.39) must match the runner's glibc. If ubuntu-latest rolls to 26.04
    # (glibc 2.40+), a dynamically-linked binary fails on Ubuntu 24.04 remotes
    # with "GLIBC_2.xx not found", surfacing as a post-install --version failure.
    runs-on: ubuntu-24.04
    timeout-minutes: 90
    permissions:
      contents: write

    steps:
      - name: Checkout sources
        uses: actions/checkout@v4

      - name: Cache Rust build artifacts
        uses: Swatinem/rust-cache@v2
        with:
          key: warpinator-release

      - name: Install Linux build dependencies
        run: |
          sudo apt-get update
          sudo apt-get install -y \
            build-essential cmake pkg-config \
            libssl-dev libfreetype-dev libexpat1-dev libgit2-dev \
            libfontconfig1-dev libasound2-dev libclang-dev

      - name: Install protoc
        run: |
          PROTOC_VERSION="25.1"
          PROTOC_ZIP="protoc-${PROTOC_VERSION}-linux-x86_64.zip"
          curl -fsSL -o /tmp/protoc.zip \
            "https://github.com/protocolbuffers/protobuf/releases/download/v${PROTOC_VERSION}/${PROTOC_ZIP}"
          sudo unzip -o /tmp/protoc.zip -d /usr/local bin/protoc 'include/*'
          rm /tmp/protoc.zip
          protoc --version

      - name: Install Rust toolchain
        run: |
          rustup show active-toolchain || rustup toolchain install
          rustup component add rustfmt clippy

      - name: Build warp-oss (release)
        run: |
          cargo build --release --bin warp-oss --features gui

      - name: Package remote-server tarball
        run: |
          strip target/release/warp-oss
          cp target/release/warp-oss oz
          tar czf oz-linux-x86_64.tar.gz oz
          rm oz

      - name: Create GitHub Release and upload tarball
        uses: softprops/action-gh-release@v2
        with:
          files: oz-linux-x86_64.tar.gz
          generate_release_notes: false
          body: |
            Warpinator remote-server daemon for Linux x86_64.

            Populates the local SCP-fallback cache automatically on fresh installs.
            To pre-stage manually:
            ```
            mkdir -p ~/.cache/Warp-Oss/remote-server/tarballs/unversioned/linux-x86_64
            curl -fsSL https://github.com/${{ github.repository }}/releases/latest/download/oz-linux-x86_64.tar.gz \
              -o ~/.cache/Warp-Oss/remote-server/tarballs/unversioned/linux-x86_64/oz.tar.gz
            ```
```
